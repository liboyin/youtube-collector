# T50: Fail any test that opens a connection beyond loopback

**Outcome:** Implemented; every test runs under a guard that refuses, reports and fails the test for any connection, datagram or forward or reverse lookup beyond loopback, in-process and in the lifecycle service process. Gates, mutation evidence and review passed after two Blocking findings were fixed.

Evidence: validated by reading `tests/conftest.py`: it owns threads and loopback servers but nothing prevents a test, or code under test, from connecting to an external host. [AGENTS](../../AGENTS.md#tests) forbids such connections; today that rests on every test substituting its fakes correctly. This is a preventive safeguard: no test is known to contact an external service.

Outcome: a suite-wide, automatically applied guard that makes a connection attempt to anything other than loopback fail the test with a message naming the destination, including name resolution of external hosts. Loopback traffic to the suite's own servers keeps working. Subprocesses the suite starts, such as the lifecycle service, get an equivalent guard, because an in-process patch does not reach them.

Direction: state the mechanism and its limits as assumptions; an in-process guard at the socket layer does not constrain child processes such as ffmpeg or Deno, so say what is and is not covered. The guard is test-owned process state and must be restored after each test.

Paths: `tests/conftest.py`, `tests/lifecycle_service.py`, `tests/tooling/` for the guard's own tests, `tests/README.md`. Compatibility surface: none; tests only. Validation: tests that an external connection and an external lookup fail under the guard and that loopback succeeds, in-process and in the lifecycle subprocess, using a non-routable or reserved destination so that a failing guard still reaches nothing real; the full suite passes in random order. Dependencies: none; [T46](../open/T46.md) and [T47](../open/T47.md) benefit from it.

## Origin and boundary

Decided by DESIGN C58; recommended first in [TODO](../TODO.md#recommended-order) beside [T45](T45.md). Revalidated at `09435bd`: `tests/conftest.py` still has no guard, and the suite's only child Python process is the lifecycle service in `tests/lifecycle_service.py`, started by `tests/test_main.py`; the tooling tests start bash scripts. Planned to commit after T45, whose new tests drive a real `YoutubeDL` against loopback servers and so exercise the guard's loopback allowance.

- **Intent:** a connection attempt or name lookup for anything other than loopback, by a test or by the code under test, fails the test with a message naming the destination ([AGENTS](../../AGENTS.md#tests), C58).
- **Dependencies:** none.
- **Implementation direction:** a new module `tests/network_guard.py` replaces, on the Python `socket` layer, `socket.socket.connect`, `connect_ex`, `sendto` and `sendmsg`, and the module functions `getaddrinfo`, `gethostbyname`, `gethostbyname_ex`, `gethostbyaddr` and `getnameinfo` (the last three and `sendmsg` added after review findings 1 and 2). A replacement allows loopback (IPv4 `127.0.0.0/8`, `::1`, `localhost` and names under `.localhost`, and a `None` host) and non-IP socket families such as Unix sockets; otherwise it records the destination and raises `ExternalNetworkError`, an `OSError`, so code under test fails as on a refused connection rather than hanging. Raising alone cannot fail a test whose code under test swallows `OSError`, so failure comes from the record: an autouse fixture in `tests/conftest.py` installs the guard with `monkeypatch` for each test, which restores the originals, and fails the test at teardown when anything was recorded. The lifecycle service installs the same guard for its whole process before running the entrypoint and writes each blocked destination to its output with a fixed marker; `Lifecycle.close` in `tests/test_main.py` fails the test when any service log holds the marker. A `connect-to` control file lets a test make the service's fake media adapter open a connection, so the guard is tested in the child.
- **Decisions within DESIGN's latitude (assumptions):** (1) The guard covers Python code using the `socket` module, which includes `http.client`, `urllib`, `requests`/`urllib3`, asyncio, uvicorn and yt-dlp's handlers (`curl_cffi` is not installed). It does not cover native code that opens its own sockets, or non-Python children such as ffmpeg, Deno and the bash scripts the tooling tests run; no test starts ffmpeg or Deno today, and C58's later layers (T46, T47) state their own coverage. (2) An IP literal outside loopback is refused at lookup too, so `getaddrinfo('192.0.2.1', …)` fails like a name; nothing in the suite resolves a non-loopback literal. (3) The guard is per test, not per session, as the task requires; background work between tests is already forbidden. (4) A test of the guard itself takes the recorded violations, so its own deliberate attempts do not fail it.
- **Compatibility surface:** none; tests only. `tests/README.md` documents the guard.
- **Non-goals:** guarding children other than the lifecycle service; inbound connections and `bind`, which reach nothing external; a firewall or network namespace, which the devcontainer cannot provide without privileges.
- **Validation:** `tests/tooling/test_network_guard.py`: under the autouse guard, each replaced entry point and `create_connection` toward reserved destinations (`192.0.2.1`, from TEST-NET-1, RFC 5737, and `example.invalid`, RFC 2606) fail naming the destination and are recorded; a swallowed attempt still fails at teardown; loopback by address and by `localhost` works against a loopback server; Unix sockets work; the originals are restored after uninstalling. `tests/test_main.py`: the lifecycle service refuses an external connection and lookup, reports it with the marker and `Lifecycle.close` would fail on it, while its loopback connection to a test-owned listener succeeds. The full suite passes in random order.
- **Mutation evidence:** the safeguard against a test reaching an external service is a security-relevant invariant, so: the autouse fixture not installed; teardown not checking the record; `getaddrinfo` left unguarded; loopback test widened to accept any address; the lifecycle service not installing the guard; `Lifecycle.close` ignoring the marker.
- **Done:** gates, adversarial review, closed record; no host check is needed.

## Implementation

`tests/network_guard.py`: `NetworkGuard` replaces `socket.socket.connect`, `connect_ex`, `sendto` and `sendmsg` and the module functions `getaddrinfo`, `gethostbyname`, `gethostbyname_ex`, `gethostbyaddr` and `getnameinfo`; `is_loopback` decides what passes; a refusal is reported, then raised as `ExternalNetworkError`, an `OSError`; `guard_process` guards a whole process and reports on standard error with `MARKER`. `tests/conftest.py`: the autouse `network_refusals` fixture installs the guard in its own `MonkeyPatch` context for each test, fails the test at teardown when anything was refused, and offers `take()` for deliberate refusals. `tests/lifecycle_service.py` guards its process before running the entrypoint and honors a `connect-to` control file; `Lifecycle` in `tests/test_main.py` collects refusals from the service logs and fails at `close` unless `expect_refusals` is set. `tests/tooling/test_fixtures.py` copies the guard beside the conftest for its nested runs. `tests/README.md` documents the guard and its limits.

## Mutation evidence

Required: the guard protects against tests reaching external services. The main agent was the primary producer, using `mutate.py` on an isolated copy of the frozen worktree with both new files named as untracked (candidate fingerprint of the first run `da4b536c3454c7b0bcf3d01944d433e0f608a15641717d738b1a323f654b7725`, 120 files; rerun on the final candidate after the review fixes), seed `20261108`, one fresh process per mutant with `-p no:cacheprovider --show-capture=no` and the named tests. Import provenance was verified for every run and no thread survived. All eleven were killed on behavior on the final candidate:

- **G1, the fixture not autouse:** the nested swallowing test passed teardown, and the nested test found the socket layer unguarded.
- **G2, teardown not asserting the record** (`assert not attempts, …` → `del attempts`): the swallowed attempt passed.
- **G3, `getaddrinfo` unguarded:** the lookup and `create_connection` cases were not refused.
- **G4, `is_loopback` returning `True` for everything:** every rejection and refusal case failed.
- **G5, `connect` unguarded:** the TCP connect cases were not refused (bounded by a 1-second socket timeout).
- **G6, the lifecycle service not calling `guard_process`:** the child's failures carried no refusal and its log no marker.
- **G7, `Lifecycle.close` not asserting refusals:** the logged refusal did not fail it.
- **G8, the guard installed with plain `setattr`:** the socket layer was still guarded after teardown.
- **G9, `gethostbyaddr` unguarded; G10, `getnameinfo` unguarded; G11, `sendmsg` unguarded:** their cases were not refused.

On the first run G3 was invalid, not surviving: its cases failed, but a failed assertion skipped `take()`, so teardown errored as well. The test now takes refusals in a `finally`. Under G3, G6, G9 and G10 the unguarded lookups of `example.invalid` and reverse lookups of `192.0.2.1` went to the system resolver, and under G5 and G6 connections to `192.0.2.1` timed out; the reserved destinations reach no real host.

## Limitations

The guard covers Python code that uses the `socket` module. Native code opening its own sockets and child processes other than the lifecycle service, such as ffmpeg, Deno and the shell scripts the tooling tests run, are not covered, as `tests/README.md` states. Rarely used entry points such as `sendmsg_afalg` (a kernel crypto socket, not IP) are not replaced. No firewall or network namespace backs the guard.
