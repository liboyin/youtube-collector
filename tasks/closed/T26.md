# T26: Make the coverage gate refuse a foreign package

**Outcome:** Implemented; the coverage gate refuses a `youtube_collector` that resolves outside the working tree, and mutation evidence and review passed with no findings.

Make the coverage gate refuse a foreign package. Evidence: validated on 2026-11-07, recorded in [T13](../closed/T13.md#validation): in a separate worktree without `PYTHONPATH`, `./check-coverage.sh` imported the main tree's package through the editable install and measured the wrong files. Paths: `check-coverage.sh`, `tests/tooling/test_check_coverage.py`, README Testing. Outcome: before pytest runs, the gate fails with a message unless `youtube_collector` resolves to the working directory's package. Validation: tests for a matching and a foreign package location, and mutation evidence that removing the check lets a foreign package pass. Dependencies: none.

## Origin and boundary

Planned from the 2026-11-07 finding above. Revalidated at `d62f023`: nothing in `check-coverage.sh` checks where the package comes from.

- **Intent:** a candidate's gate results can be trusted to describe that candidate's files ([AGENTS](../../AGENTS.md#validation-and-review)).
- **Dependencies:** none.
- **Implementation direction:** a check in `check-coverage.sh`, after the interpreter check and before pytest, using `importlib.util.find_spec` so nothing is imported. It runs as `python3 -P`, because `python3 -` puts the working directory on `sys.path` and pytest's console script does not.
- **Decisions within DESIGN's latitude (assumptions):** a missing package and a foreign package give the same message, since the remedy is the same.
- **Compatibility surface:** the gate's command line and its exit codes are preserved; it exits non-zero in one new case. No HTTP, setting or on-disk layout is affected.
- **Non-goals:** the worktree helper (T27); changing the coverage policy.
- **Validation:** tests in `tests/tooling/test_check_coverage.py` for a matching and a foreign location, run in owned directories with `PYTHONPATH`, and a real run in a worktree of this repository with and without `PYTHONPATH`.
- **Mutation evidence:** the comparison disabled, `-P` dropped, and the check's exit status ignored.
- **Done:** gates, review, closed record. No host checks.

## Implementation

`check-coverage.sh` gains the check before pytest; `tests/tooling/test_check_coverage.py` covers a foreign and a matching location, and its helper now gives every run an owned package through `PYTHONPATH`. README Testing says the gate refuses instead of asking the reader to confirm the import by hand.

## Validation

Environment: the devcontainer, Python 3.14.4, 2026-11-08, base `d62f023`. Baseline: the gates passed at `9fbf3a1` ([T33](T33.md#validation)); `d62f023` adds only documentation. Final candidate: `./check-coverage.sh` passed (543 tests, every file 100% statement and branch); `mypy youtube_collector` and `ruff check .` passed.

A real git worktree of `d62f023` plus the candidate's script and test: without `PYTHONPATH` the gate refused, naming the main tree's package and the worktree's; with `PYTHONPATH` set to the worktree it passed.

## Mutation evidence

Each mutant failed `test_a_package_from_another_tree_fails_without_running_pytest`: M1, the comparison disabled; M2, `-P` dropped; M3, the check's exit status ignored. In each, pytest ran for a foreign package.

## Review

## Limitations

A package that imports from the working tree but is not the tree's own, such as a symlinked directory, passes only if it resolves to the same path.
