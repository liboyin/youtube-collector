# T13: Compose project names

**Outcome:** Implemented; gates, simulated `docker compose config` and review passed; the host check is in T10.

## Origin and boundary

From the T10 host check on 2026-11-07 at `bf7dc39`, recorded in [T2](T2.md#host-checks). The boundary, as accepted in TODO:

- **Intent:** let the devcontainer and the production service coexist on one Docker daemon (C28). Today both run as Compose project `youtube-collector`, so a root `docker compose up` would recreate the devcontainer's container and a root `down` would remove it.
- **Implementation direction:** the entry's proposal. Add a top-level `name: youtube-collector-service` to `docker-compose.yaml`, and `name: youtube-collector` to `.devcontainer/docker-compose.devcontainer.yaml`. The last file's `name` wins in Compose's merge, so both devcontainer configurations, which layer that override, keep the project name they have today and with it their volumes. README's configuration section and DESIGN section 7 describe the names; T10 gains the host check.
- **Revalidated (2026-11-07):** the Dev Containers CLI's `getProjectName` (`src/spec-node/dockerCompose.ts` on `main`) uses, in order: `COMPOSE_PROJECT_NAME` from the environment, then the same variable from `.env` in the CLI's working directory, then the top-level `name` of the merged configuration from `docker compose config`, then the first Compose file's directory name. The changelog first lists the `name` attribute in 0.60.0 (May 2024), with fixes in 0.62.0 and 0.64.0. An older CLI falls back to the first file's directory, the repository root, which is also `youtube-collector`, so either path yields the current name. `.env` sets no `COMPOSE_PROJECT_NAME`, checked by key name only.
- **Compatibility surface:**
  - The service's project name changes to `youtube-collector-service`, and with it the prefix of its named volumes (`collector_db`, `firefox_profile`). The service has never been deployed, so no data moves.
  - The devcontainer's project name and volumes are unchanged.
  - A `COMPOSE_PROJECT_NAME` set by the user would still override both names; README says to leave it unset.
- **Non-goals:** the service's entrypoint and published port (T24); changing the devcontainer's volumes.
- **Validation:** `docker compose config` with a checksum-verified standalone Compose binary in a scratch copy without `.env` resolves `youtube-collector-service` for the root file, and `youtube-collector` for both devcontainer stacks (real-data with placeholder paths). The host check after a rebuild goes into T10.
- **Done:** the gates (`./check-coverage.sh`, `mypy youtube_collector`, `ruff check .`), as AGENTS requires for every non-trivial configuration change, the simulated validation, review and a completion record; the host check stays in T10.
