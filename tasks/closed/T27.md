## Implementation

Three standalone scripts in `.agents/skills/adversarial-review/references/`, tested in `tests/tooling/test_review_tools.py`; the [review skill](../../.agents/skills/adversarial-review/SKILL.md) and the scratch-testing recipe link them.

- **`mutate.py`:** copies the tracked files and the untracked files named with `--untracked` into a temporary directory it owns, runs each mutant's own test selection in a fresh process with an environment built from scratch, and writes evidence as it goes. A plugin kept outside the copy writes each run's own report: why each test failed, which modules loaded and which threads are alive. A kill needs a test failure through an assertion, no errors, and verified provenance. Each entry records a SHA-256 of the copy, a fixed `pytest-randomly` seed and the failure details.
- **`dispatch.py`:** reads the target's `HEAD` when it writes the prompt, runs the Codex CLI with stdin closed, and prints the session ID and report. `--resume` continues a recorded reviewer.
- **`worktree_gates.py`:** creates a detached worktree from `HEAD` plus the named files, including deletions, and runs every gate there with `PYTHONPATH` set to it.

## Review

Codex `gpt-6.1-sol`, medium effort (dispatch arguments), thread `01a1bb2a-e46f-7462-9b03-bd269d1dfec2`, on the dirty tree.

- **First assessment, four Blocking findings, all validated and fixed:**
  1. `worktree_gates.py`: a symlinked parent could redirect a removal outside the worktree. Parents are now checked in the repository and in the new worktree before anything is written.
  2. `mutate.py`: an absolute symlink or a symlinked parent could reach outside the copy. Both are now refused.
  3. `mutate.py`: every non-ignored untracked file was copied. `--untracked` is now an allowlist.
  4. `mutate.py`: a `SyntaxError` inside a test counted as a kill. The plugin now separates behavioral from broken-code failures.
- **Follow-up 1, three Blocking findings, all validated and fixed:**
  4. (partly unresolved) two symlink fixtures failed on a missing stub rather than on the protected property. They now have the stubs.
  5. Provenance accepted application modules from outside both trees, and could read a nested run's line. Application modules must now come from the copy, and each run writes its own report file.
  6. The `/etc/passwd` test, described above. It now uses an owned sentinel.
- **Follow-up 2:** all six resolved, no new findings. Verdict: no blocking findings.
