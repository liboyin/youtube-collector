Outcome: normal operation shuts down gracefully, while exceptional stalls may rely on Docker-enforced termination, as the user accepted in DESIGN C50. Correct the claim that the 45-second container grace prevents SIGKILL from interrupting cleanup; distinguish worker waiting, actual thread termination and process exit. Preserve C36's restart recovery and C25's accepted staging stalls. Do not add worker subprocess isolation, forceful in-process thread cancellation, new grace settings or longer grace periods merely to obtain a stronger guarantee than C50 requires; a timeout on a future does not stop a running thread. Any runtime defect exposed by validation must be investigated and bounded before fixing it.

Current sequence: uvicorn allows up to 5 seconds for outstanding request/task completion, then application shutdown asks the worker to stop and waits up to 30 seconds for it. That wait does not kill the worker; a daemon worker can still run until process exit. Closing the API database connection is queued on its executor and awaited without a bound, followed by another blocking executor shutdown. Cancelling an HTTP await does not terminate already-running SQLite work. SQLite's 30-second busy timeout bounds lock waiting, not all query or filesystem execution. Compose's 45-second stop period is an external grace before forced termination, not proof that application cleanup completes inside it. The request wait and worker wait are separate budgets, and neither includes an arbitrary executor stall.

Validation: owned subprocess tests with fake acquisition and temporary databases demonstrate clean process exit in normal operation and controlled forced termination when an exceptional stall prevents exit. Restart against the same test-owned database and assert interrupted work recovers, already-published files are not overwritten, and only complete artifacts appear at final paths. Own and reap every child process on failure too; use targeted mutation evidence for resource ownership and recovery. A test harness sending a kill signal simulates the container fallback; it does not validate Docker itself. Docker signal delivery and the 45-second escalation remain host checks under [T10](../open/T10.md). Dependencies: C50 settles the policy; coordinate connection cleanup with [T36](T36.md) without making that fix a prerequisite for documenting the existing behavior. ## Limitations

- The tests shorten uvicorn's 5-second request wait and the 30-second grace, so they validate ordering and outcome, not the real budgets.
- The stall is a blocked Python call in a real transaction. A stall inside SQLite or the filesystem was not injected.
- A killed download can leave a hidden `.staging-*` directory for manual cleanup, as C46 and C50 accept.
