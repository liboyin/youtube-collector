# T8: Slim runtime image

**Outcome:** Implemented with T3; the runtime image's contents and size (287 MB) were checked on the host (amd64).

## Origin and boundary

From the 2026-11-07 project review of `ca869a8`. Delivered with [T3](T3.md), which holds the shared environment, validation and review.

- **Intent:** the `runtime` image carries no git, uv, curl, unzip or source tree. A `build` stage builds the venv; `runtime` is `base` plus that venv, with the project installed as a regular package; `dev` continues from `build`, adding curl (the creation hook needs it), the dev group and the editable project the workspace bind mount needs.
- **Compatibility surface:** the runtime image loses the build tools and the source tree. No entrypoint exists yet, so nothing depends on them.
- **Non-goals:** the service entrypoint, a healthcheck, image size targets.

## Implementation

`Dockerfile` stages:

- `base`: ca-certificates, ffmpeg, python3 and Deno, plus the ubuntu-owned directories.
- `build`: adds git and uv, installs the dependencies, then the project with `--no-editable`.
- `runtime`: `COPY --from=build /opt/venv`, root-owned and read by the service.
- `dev`: `FROM build`, adds curl, and installs `--group dev`, which `uv pip sync` turns into an editable project install.

unzip is no longer installed anywhere, because Deno now comes from its image ([T4](T4.md)).

## Validation

In the chroot ([T3 validation](T3.md#validation)), the runtime venv imported `youtube_collector` from site-packages with the working directory at `/`, and the dev step replaced it with an editable install pointing at `/workspaces/youtube-collector`. ruff, mypy, pytest, curl, uv, git and Deno were all present for `dev`. The reviewer re-ran the runtime import after removing the source tree and git, uv, curl and unzip.

## Review

Shared with T3; no finding concerned T8.

## Host checks

Host run on 2026-11-07 at `3fb0a4f` by the user (WSL2 kernel 6.6.87.2, Docker 29.6.2) with the same untracked script, after the user pulled the local `docker-build-common` clone that `.env`'s `BUILD_COMMON_CONTEXT` names. Whether that checkout equals the pinned `v1.2.0` tag was not checked, so the build used the clone's current helpers. An earlier attempt in the same session failed because the clone predated `uv_install.sh`.

- The built `runtime` image has no `git`, `uv`, `curl` or `unzip` on `PATH`: passed.
- No source tree: passed. The script listed `/workspaces/youtube-collector` and found only `assets`, which it reported as a failure; that entry is the empty staging mount point the `base` stage creates on purpose (`Dockerfile`, so a new named volume initializes owned by `ubuntu`), and `.dockerignore` excludes `assets/` from the build context. The check was too strict, not the image.
- `youtube_collector` imports from `/opt/venv/lib/python3.14/site-packages`, a regular install: passed.
- Image size: 287 MB (287,717,581 bytes, `docker image inspect`), amd64.

## Limitations

- Contents and size are measured on amd64 only, from a build that used the user's local `docker-build-common` clone rather than the pinned tag (see Host checks).
