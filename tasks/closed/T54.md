# T54: Let the review tools take over rules that were prose

**Outcome:** Implemented. The gates, the mutation evidence and the adversarial review passed, after one Blocking and two Non-blocking findings were fixed. The same commit rewrites the review skill and the recipe, which the user reviewed.

## Origin and boundary

The user requested this ad-hoc change on 2026-11-14. The review skill and the scratch-testing recipe had grown dense with notes that agents added after friction. [AGENTS.md](../../AGENTS.md#governance-files) now says that a lesson belongs first in a tool or an error message. The user also decided that every scratch run of a review goes through `mutate.py`. This task gives the review tools the behavior that the prose described, so that a later documentation change can delete that prose.

- **Intent:**
  - `mutate.py` runs tests with no mutant (`--tests`) in the same isolated copy, with the same provenance check.
  - `mutate.py` copies a probe file into the copy (`--add SOURCE=PATH`), so that a probe needs no write to the repository.
  - `mutate.py` writes an `advice:` line for each run that is not evidence. The line gives the reason and the remedy.
  - `worktree_gates.py --compare` checks, before the commit, that the repository's working files match the reviewed files.
  - `worktree_gates.py --remove` removes the review worktree after the commit. It refuses unless the commit at `HEAD` holds the reviewed content.
  - `dispatch.py` runs `codex login status` first. If the check fails, it sends nothing and reports a blocker.
- **Dependencies:** T27 (the review tooling). No open task depends on this one.
- **Implementation direction:** changes only in `.agents/skills/adversarial-review/references/` and in `tests/tooling/test_review_tools.py`. `mutate.py` gets one function that builds the copy for both modes.
- **Decisions within DESIGN's latitude (assumptions):**
  1. A focused run exits with 0 when the tests pass and 1 when a test fails. It exits with 2 when the run is not evidence: a timeout, no verified provenance, or a pytest status other than 0 and 1.
  2. `--add` splits its value at the first `=`. The source must be a regular file. The path must be relative and must stay inside the copy.
  3. `--remove` and `--compare` take the reviewed content from the worktree itself: every path in which its files differ from its `HEAD`. Ignored files are not reviewed content. The check builds a git tree in a temporary index, so it writes objects to the shared object store but leaves the worktree's index alone.
  4. A refused removal or a difference exits with 1. A command that cannot run exits with 2.
  5. `--changed PATH` names a reviewed file that is expected to differ, and both modes skip it. A task record needs this: it gains its results after the review.
- **Compatibility surface:** none for the service: no HTTP contract, setting or on-disk layout changes. The command lines of the three tools gain options. The existing invocations keep their meaning, except that `dispatch.py` now exits with 2 when the Codex CLI is missing or not logged in.
- **Non-goals:** `snapshot.py`. The coverage policy. Automation of the integrity snapshot. The rewrite of the review skill and the recipe is a documentation change outside the reviewed candidate. It needs the user's review, and [Documentation](#documentation) describes it.
- **Validation:** new tests in `tests/tooling/test_review_tools.py` for each behavior and each refusal. The three gates.
- **Mutation evidence:** the refusal to remove a worktree whose reviewed content is not committed protects against data loss. The containment of `--add`, the login blocker and the exit status of a focused run that is not evidence protect against wrong acknowledgement or escape.
- **Done:** gates, adversarial review, this record. No host check is needed.

## Implementation

- `mutate.py`:
  - `scratch_copy` builds the isolated copy for both modes and writes the evidence header.
  - `run_focused` runs the tests named with `--tests` against the unmutated copy.
  - `parse_additions` and `add_file` implement `--add SOURCE=PATH`. The evidence gets one `ADDED` line with a SHA-256 for each added file.
  - `advice` returns the reason and the remedy for a run that is not evidence. Mutant reports, focused reports and the baseline error carry it.
- `worktree_gates.py`:
  - `reviewed_content` builds a git tree of the worktree's files in a temporary index, and lists the paths that differ from the worktree's `HEAD`.
  - `compare` implements `--compare`, and `remove` implements `--remove`. Both skip the files named with `--changed`.
  - The module docstring no longer recommends plain `git worktree remove`, which refuses for a review worktree.
- `dispatch.py`: `login_problem` runs `codex login status` before anything is sent. A failure prints the blocker text and exits with 2.
- `tests/tooling/test_review_tools.py`: tests for each new behavior and each refusal. The `codex` stub answers the login check.

## Review

Reviewer: an independent Codex CLI session started by `dispatch.py`, session `01a1da55-97ba-7ba0-b417-67ab5dd924d1`. The dispatch arguments were model `gpt-6.1-sol` and effort `medium`. The target was the frozen worktree. The integrity snapshots before and after each assessment were identical.

First assessment: one Blocking finding. The reviewer accepted the gates and the eight mutation kills of that candidate, and ran five probes of its own.

1. **Blocking, validated, fixed.** With `core.filemode=false`, the temporary tree dropped a change of the executable mode. `--compare` then returned 0, and `--remove` deleted a worktree that held the uncommitted mode change. Fix: `reviewed_content` adds the files with `git -c core.filemode=true`. The new test `test_worktree_gates_see_a_mode_change_that_git_is_configured_to_ignore` covers both modes, and mutant M9 shows that it fails without the option.
2. **Non-blocking, validated, fixed.** A baseline that was not evidence, such as a timeout, stopped the batch with status 2 but gave no advice. Fix: the baseline error carries an `advice:` text. `test_mutate_explains_a_baseline_that_is_not_evidence` covers three such baselines, and the failing-baseline test asserts its own advice.

The reviewer also noted that the working record gave a test count that differed from the gate log. The record was corrected.

Follow-up on the refrozen candidate, same session: **no blocking findings, and both earlier findings resolved.** The reviewer checked both fixes and the refreshed evidence, and reran its probes and the affected tests in scratch copies: 11 passed with verified imports. It accepted the full gates from the supplied results.

After that verdict, the main agent found a gap of its own: `--remove` would refuse for every task, because the task record gains its results after the review. `--changed` was added with a test and mutant M10, and the candidate was frozen again. Third assessment, same session: **no blocking findings**, with 16 focused cases of the reviewer's own, all passed.

3. **Non-blocking, validated, fixed.** The record in the candidate still gave the test count and the mutants of the earlier candidate. This record now describes the final candidate: 763 tests, ten mutants and three assessments.

## Limitations

- `run_tests` in `mutate.py` reads every output line that starts with `ERROR` as an errored test. A nested pytest's own output can therefore make a run INVALID. This weakness predates the task and is not fixed here. It errs toward INVALID, never toward KILLED.
- If the repository has `core.filemode=false`, git cannot commit a mode change. `--remove` then refuses for a candidate that changes a mode, and the worktree must be removed by hand.
- This record was completed after the last assessment, so the committed record differs from the reviewed one. The tool changes and the tests are identical to the reviewed files, as `worktree_gates.py --compare --changed tasks/closed/T54.md` confirmed.
- The timeout paths are tested with simulated runs, not with a real timeout.
