# T38: Give the caption HTTP session explicit lifecycle ownership

**Outcome:** Implemented; the worker thread closes the caption session the service created when its run ends, so an abandoned worker cannot lose it mid-use, and injected clients stay with their owners. Gates, mutation evidence and review passed after two Blocking findings were fixed.

Evidence: [review F4](../../project-review-2026-11-10.md#f4--low-caption-http-session-ownership-is-implicit), source inspection at `d565907039b7550f550d860f3d4fdd2891ebc8d4` including the installed transcript client. `CaptionClient` creates a requests Session without an explicit close owner; the transcript client exposes no cleanup API. No production resource exhaustion was observed.

Paths: `youtube_collector/captions.py`, composition/lifecycle in `youtube_collector/api.py` and `worker.py`, and their tests. Outcome: explicitly own and close the internally created HTTP session when its worker has actually stopped; preserve ownership of injected clients and do not close resources concurrently with a worker abandoned after the grace period. Validation: repeated lifespans, ordinary completion, startup failure where applicable and slow-worker shutdown, with owned fake sessions proving correct close timing and no use after close. Include targeted mutation evidence for concurrent resource ownership. Dependencies: coordinate with [T37](T37.md) on shutdown ownership and [T39](../open/T39.md) if the caption backend changes; do not build a general resource framework for this cleanup.

## Origin and boundary

Raised by the [2026-11-10 project review](../../project-review-2026-11-10.md#f4--low-caption-http-session-ownership-is-implicit). Revalidated at `c89e96c`: `CaptionClient` creates a `requests.Session` that nothing closes, and the transcript client has no cleanup API. [T39](../open/T39.md) is deferred (C52) and may change the backend; this task covers the current one.

- **Intent:** the service closes the caption HTTP session it created, once and only after the worker that uses it has actually stopped.
- **Dependencies:** [T37](T37.md), which established the shutdown wording.
- **Implementation direction:** `CaptionClient.close` closes only a session the client created. `Components.release`, a no-op by default, is set by `default_components` to that method. `Worker.run` calls its new `on_stopped` callback in a `finally`, on the worker's own thread, so an abandoned worker closes the session itself when it eventually finishes, and nothing can close it while it is in use. `_Runtime.start` and the lifespan call `release` themselves only when no worker thread exists: a failure building the runtime, or `RuntimeError` from `Thread.start`. An interruption while `Thread.start` waits can arrive after the thread began, so the worker is asked to stop and releases as usual.
- **Decisions within DESIGN's latitude (assumptions):** releasing on the worker thread rather than in `_Runtime.stop` removes any need to compare `is_alive` with the worker's real progress, and the session has only ever been used on that thread. A worker that never finishes before the process exits leaves the session to process exit, which the review already judged harmless. A hook on `Components` keeps fakes free of a `close` they do not need and leaves injected clients with their owners.
- **Compatibility surface:** no HTTP contract, setting or on-disk layout changes. `Worker` and `Components` gain optional fields.
- **Non-goals:** a general resource framework; closing the yt-dlp downloaders, which already close per call; authenticated captions (T39); the transcript client's timeout or retry behavior.
- **Validation:** fake sessions and fake adapters for ordinary completion, repeated lifespans, a runtime that cannot be built, a worker thread that cannot be created, an interrupted start with the thread already running, a worker that dies during recovery, and a slow worker abandoned at shutdown that still uses captions afterwards, with the release coming after that last use. An injected client is never closed.
- **Mutation evidence:** release moved to `_Runtime.stop`, so it runs beside an abandoned worker; release skipped when the worker dies; an injected client's session closed; startup failure not releasing; `default_components` not wiring the hook.
- **Done:** gates, adversarial review, closed record; no host check is needed.

## Implementation

`youtube_collector/captions.py`: `CaptionClient` remembers the session it creates, and `close` closes only that one. `youtube_collector/worker.py`: `on_stopped`, called in a `finally` at the end of `run`, on the worker thread. `youtube_collector/api.py`: `Components.release`, a no-op unless `default_components` sets it to `CaptionClient.close`; a failed runtime build, or `RuntimeError` from `Thread.start`, releases at once, and any other interruption of `Thread.start` asks the worker to stop and leaves the release to it. `DESIGN.md` section 14 states the rule. Tests are in `tests/test_captions.py`, `tests/test_worker.py` and `tests/test_api.py`.

## Validation

Environment: the devcontainer, Python 3.14.4, 2026-11-09, base `c89e96c`. Final candidate in its own worktree with `PYTHONPATH` at that root: `./check-coverage.sh` passed with 638 tests at 100% statement and branch for every file; `mypy youtube_collector` and `ruff check .` passed.

## Mutation evidence

The main agent was the primary producer, using `mutate.py` on an isolated copy with seed `20261108` and `--show-capture=no`, one fresh process and test selection per mutant, rerun on the final candidate. No thread survived. All eleven failed on behavior:

- **M1, release beside an abandoned worker** (`_Runtime.stop`): `['released'] == []` while the worker was still running.
- **M2, no `finally`** around the run: a worker that died in recovery released nothing.
- **M3, a session created for an injected client:** `timeout_session` was called.
- **M4, a failed runtime build not releasing:** `[] == [1]`.
- **M4b, thread creation failure not releasing:** `[] == [1]`.
- **M5, `default_components` not wiring the hook:** `close` not called.
- **M6, the worker not given the hook:** no release after a lifespan.
- **M7, `close` doing nothing:** `0 == 1`.
- **M8, the release on another thread:** the recorded thread was not the worker's.
- **M9, an interrupted start releasing beside the running worker:** the release came from the wrong thread.
- **M10, an interrupted start not stopping the worker:** the worker was still alive after 10 seconds, observed before the test's own cleanup.

## Review

Codex `gpt-6.1-sol`, medium effort (dispatch arguments), session `01a1c0db-e7bc-7472-a14b-84a5c6dae33a`, on the frozen worktree, in three assessments.

1. **Blocking, `api.py`:** the lifespan released on any startup exception, but `Thread.start` starts the native thread before waiting on it, so an interruption there can arrive with the worker running. Validated against CPython 3.14's `Thread.start`; the reviewer reproduced it by injecting `KeyboardInterrupt` at that wait. Fixed as described under Implementation. Resolved in the second assessment.
2. **Blocking, `tests/test_api.py`:** the new interrupted-start test left the worker running if the production stop request was missing. Validated by reading the test. Fixed with an unconditional stop and join in a `finally`, with the observation taken before that cleanup. Resolved in the third assessment; the reviewer replayed the mutants that bear on it.

Final verdict: no blocking findings. No Non-blocking findings or Nits. Integrity snapshots matched each time.

## Limitations

- A worker that never finishes before the process exits leaves the session to process exit, as the project review judged harmless.
- An interruption that arrives before `Thread.start` creates the thread leaves an unused session to process exit; startup is failing at that point.
- [T39](../open/T39.md) may replace this backend, which would retire `CaptionClient.close`.
