**Outcome:** The fixes are ported and committed without their gates and review, at the user's direction. [T64](T64.md) runs them.

## Origin and boundary

The user asked on 2026-11-23 to port the fixes that youtube-whisperer's adversarial review of its T2 (commit `560aa11`) made to the tools it had copied from this repository. That review found seven containment and data-loss defects in `mutate.py`, `worktree_gates.py` and `check-coverage.sh`, and each holds here too.

- **Intent:** this repository's `mutate.py`, `worktree_gates.py`, `check-coverage.sh` and their tests match youtube-whisperer's at `560aa11`, apart from the package name.
- **Dependencies:** youtube-whisperer `560aa11`.
- **Implementation direction:** copy the five files from youtube-whisperer, with `youtube_whisperer` renamed to `youtube_collector`. To keep the files identical, this also brings mode 755 for the two scripts and an explicit `check=False` on two `subprocess.run` calls.
- **Assumptions:** the scripts are run with `python3`, so the mode change affects nothing.
- **Compatibility surface:**
  - A worktree frozen by the earlier `worktree_gates.py` has no freeze record, so `--compare` and `--remove` refuse it. Freeze it again.
  - `check-coverage.sh` also refuses a symlinked package that resolves outside the working directory.
  - `mutate.py`'s candidate digest has a new format, so it does not match the digests in earlier records.
  - No HTTP contract, setting or on-disk layout of the service changes.
- **Non-goals:** the two documentation mitigations that youtube-whisperer added to its skill for the deferred findings below. They are governance edits here, and are proposed to the user separately. Ruff's configuration.
- **Validation:** the tooling tests, the mutants below, the three gates, the documentation check and the review.
- **Mutation evidence:** each fix, and the package name in each tool.
- **Done:** passing gates, an independent review without Blocking findings, and this record. The user chose on 2026-11-23 to commit and push before the gates and the review, which T64 runs.

## Implementation

- **`mutate.py`:**
  - It checks each copied symlink again in the copy, because surplus `..` components stop at `/` in the repository but not in the deeper copy.
  - It refuses a mutant path that is absolute, climbs out of the copy, or is or lies below a symlink.
  - It writes the mutant, and later the original, to a new file with the original mode that replaces the path atomically. A symlink or hard link that a test put in place therefore never carries a write out of the copy. The next mutant starts from the same mode. It stops the batch if a test replaced a parent with a link.
  - Its candidate digest covers each file's kind and mode.
- **`worktree_gates.py`:** the freeze records the worktree's `HEAD` and the named paths with their fingerprints in the worktree's own git directory. `--compare` and `--remove` refuse a worktree without a readable record, or whose `HEAD`, named files or unnamed paths changed since. `--remove` also refuses while the worktree's index stages a change.
- **`check-coverage.sh`:** the resolved package must lie inside the working directory.
- **README:** the coverage gate's refusal of a symlinked package.

## Review

Not performed. The user waived it for this commit on 2026-11-23, so this is not a passed review. [T64](T64.md) runs it in this repository's devcontainer.

Two non-blocking findings of youtube-whisperer's review apply here too and are deferred there with documentation mitigations:

- A `TypeError` or `AttributeError` that the mutated code itself raises counts as `KILLED`, because a `TypeError` can also be a genuine behavioral failure. A kill's failure detail needs reading before it counts as evidence.
- `mutate.py` copies every tracked file from the working tree, so unrelated dirty tracked files enter the copy. Freezing the candidate with `worktree_gates.py` first, and passing the worktree with `--repo`, avoids that.
