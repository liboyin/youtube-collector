# T61: Refuse the process exit in every test

**Outcome:** Done. An autouse guard refuses `os._exit` in every test, and the service's default exit looks it up at call time.

## Origin and boundary

Ad-hoc change requested by the user on 2026-11-17, from the optional hardening that the T35 handoff proposed. [T35](T35.md) gave `api.Components` a default `exit_process` of `os._exit`. API tests stayed safe only because each one injected a refusing exit, so a new test that forgot it could end the whole test run without a report.

- **Intent:** no test can end the pytest process through the service's fatal exit, whatever components it builds.
- **Dependencies:** T35 and DESIGN C53.
- **Implementation direction:** a named default, `api._exit_now`, calls `os._exit` at call time. The autouse fixture `process_exits` in `tests/conftest.py` replaces `os._exit` with a refusal that raises and records the attempt, and fails the test at teardown on any attempt left untaken. The API tests drop their own refusing exit.
- **Decisions within DESIGN's latitude (assumptions):** the guard follows the network guard's pattern: refusal at the attempt, a record that decides at teardown, and `take()` for a deliberate attempt. Child processes, such as the lifecycle service, do not load the guard and keep their real exit, which their tests require.
- **Compatibility surface:** none. The default exit behaves as before.
- **Non-goals:** changes to the fatal exit's behavior.
- **Validation:** nested pytest runs show that a swallowed attempt fails teardown, that an attempt on another thread fails the test, and that a taken attempt passes. An API test shows that the default exit reaches the guard. The three gates.
- **Mutation evidence:** "no test can end the pytest process", through each of the default lookup, the guard's patch and its teardown check. Each probe is safe under its mutant: the nested runs exit only their own process, and the API test checks the default's identity before it calls it.
- **Done:** gates, review, this record.
