# T57: Report the incoming references to a file or a heading

**Outcome:** Implemented. `./check_docs.py --references <target>` lists each line that links to a file, a directory or a heading. The gates passed, and the adversarial review reported no finding.

Add an optional report to `check_docs.py` (the documentation check of [T55](T55.md)). Evidence: the user accepted the scope on 2026-11-15, from a handover that another agent wrote. Before an agent renames a file or a heading, it needs the lines that link to it. A text search misses reference-style links and relative paths that are written differently.

Paths: `check_docs.py`, `tests/tooling/test_check_docs.py`, `README.md`. Outcome: `./check_docs.py --references <file-or-heading>` lists each source line that links to the target. Validation: the acceptance criteria below. Dependencies: T55.

## Origin and boundary

The user accepted these decisions before this task was recorded:

- Extend `check_docs.py`. Do not add a second link checker or a new skill.
- The report and the default check share one link parser.
- The report edits no file, and it is not a required check. No generated index is committed.
- Semantic consistency stays with the review. A passing check means only that the local documentation references resolve.
- The request concerns documentation links. It does not concern dependencies between tasks.

The boundary:

- **Intent:** `./check_docs.py --references AGENTS.md` lists each line that links to that file or to one of its headings. `./check_docs.py --references 'AGENTS.md#governance-files'` lists only the links to that heading.
- **Dependencies:** T55.
- **Implementation direction:**
  - A new function `links` extracts the links of a text with their lines. `check_links` and the report both use it.
  - A new function `locate` resolves a destination to a file and a fragment. `link_problem` and the report both use it.
  - A new function `references` validates the query and collects the matching lines. `main` gains the option.
- **Decisions within DESIGN's latitude (assumptions):** the user accepted the first eight on 2026-11-15, as the handover proposed them.
  1. The query path is relative to the root of the repository, also when `--repo` selects another checkout.
  2. The report replaces the default check for that run. It certifies nothing about the documentation.
  3. The exit status is 0 for a completed report, also with no match. It is 2 for an invalid query or an unreadable file.
  4. The exit status 1 keeps its meaning: the default check found a problem.
  5. A source line appears once, even if it links to the target twice.
  6. For a reference-style link, the report names the line that uses the label, not the line of the definition.
  7. A definition that no line uses is not a reference. The default check still validates its destination.
  8. A link from the target file to itself is a reference.
  9. A query may name a directory. The report then lists the links to exactly that directory, not to the files in it.
  10. The query path is taken as written, without URL decoding. The fragment is the anchor as GitHub derives it from the heading.
- **Compatibility surface:** none for the service. The default invocation, `--repo` and the exit statuses of `check_docs.py` are preserved.
- **Non-goals:**
  - Task dependency analysis, automatic link edits and checks of external URLs.
  - Interpretation of prose, and inferred links between code and documentation.
  - A broader Markdown grammar. A shortcut reference such as `[label]` alone stays unsupported, like a destination with deeply nested parentheses.
- **Validation:** tests in owned repositories for these criteria.
  1. A file query finds direct links and links to its headings.
  2. A heading query excludes links to other headings and links without a fragment.
  3. Relative links from different directories resolve to the same target.
  4. An encoded path and an encoded fragment match the same target.
  5. A reference-style link is reported at its usage line. An unused definition is not reported.
  6. Text in a code span or in a fenced code block gives no reference.
  7. No match gives status 0 and an explicit count of zero.
  8. A missing target, a missing heading and a path outside the repository give a clear error and status 2.
  9. The output is sorted by path and line, and each line appears once.
  10. `--repo` scans the selected repository, not the working directory.
  11. A query or a link through a symbolic link cannot name or read a file outside the repository.
  12. The report leaves the files and the Git index unchanged.
  13. The existing tests of the default check pass without change.
- **Mutation evidence:** none is required. The containment code of T55 is reused without a change in behavior, and the user confirmed this on 2026-11-15.
- **Done:** the three gates, `./check_docs.py`, the adversarial review and the closed record. [README Testing](../../README.md#testing) describes the option. No host check is needed.

## Implementation

- `check_docs.py`:
  - `links` extracts the inline links, the link definitions and the uses of a label from a text. `check_links` and the report both use it.
  - `locate` resolves a destination to a path and a fragment, and states whether the path stays in the repository. `link_problem` and the report both use it.
  - `references` validates the query and collects the matching lines.
  - `main` gains `--references`. With it, the tool prints the report and runs no check.
- `tests/tooling/test_check_docs.py`: 20 new tests. The 59 tests of T55 are unchanged.
- [README Testing](../../README.md#testing) describes the report, and it states that a passing check means only that the local references resolve.

## Limitations

- The report lists Markdown links only. It does not find a path in code, in a code span or in plain text.
- A shortcut reference, such as `[label]` without a second pair of brackets, is not recognized. A destination with more than one level of nested parentheses is not recognized either.
- The fragment of a query must be the anchor exactly as GitHub derives it. The comparison is case-sensitive.
- This record was completed after the assessment, so the committed record differs from the reviewed task file. The script, the tests and the other documentation files are identical to the reviewed files.
