# T15: URL parsing

**Outcome:** Implemented; mutation evidence and review passed.

## Origin and boundary

Planned by [T9](T9.md). The accepted boundary, as it stood in TODO:

- **Intent:** DESIGN 5.2 with C16 and C21. Turn a submitted URL into a single-video or playlist target syntactically, without contacting YouTube.
- **Implementation direction:** `parse_target(url) -> VideoTarget | PlaylistTarget`, raising `UnsupportedUrlError` (a `ValueError`) whose message is the caller-facing reason. The scheme is `http` or `https` and the network location, lowercased, is exactly `youtube.com`, `www.youtube.com`, `m.youtube.com` or `youtu.be`, so ports and user information are rejected. Video forms: `youtu.be/<id>`, `/watch` with exactly one `v` value, `/live/<id>` and `/shorts/<id>`, each with an optional trailing slash. A video ID is 11 characters from `A–Z a–z 0–9 _ -`. `/playlist` takes exactly one `list` value of one or more of the same characters; an ID starting `RD` is rejected as a Mix. A watch URL's `list` and any other query parameters and fragments are ignored. Channel paths (`/channel/`, `/c/`, `/user/`, `/@…`) get a channel-specific reason, and anything else a generic one. Each target exposes its canonical URL (`https://www.youtube.com/watch?v=<id>` or `https://www.youtube.com/playlist?list=<id>`), the only URL the worker passes to yt-dlp, so a video target can never expand into a playlist.
- **Assumption:** the source revision's `get_video_id` is not available in this repository; the 11-character alphabet is YouTube's video ID format, which a stricter check than "any non-empty string" keeps out of file names. Effect: a malformed ID is rejected with 422 rather than failing on the worker.
- **Compatibility surface:** the later 422 reasons of the submission endpoints (T24).
- **Non-goals:** other hosts such as `music.youtube.com` or `youtube-nocookie.com`, embed URLs, and checking that an ID exists.
- **Validation:** tests for every accepted form on every host and scheme, `v` with `list`, trailing slashes, ignored parameters, and rejection of channels, handles, tabs, Mix playlists, malformed IDs, missing or repeated `v` and `list`, extra path segments, ports, user information and other schemes and hosts. Mutation evidence for the Mix rejection and for a watch URL with `list` staying a video.

## Implementation

`youtube_collector/urls.py`: `parse_target`, `VideoTarget`, `PlaylistTarget` and `UnsupportedUrlError`, with `urllib.parse.urlsplit` and `parse_qs` and a `match` over the path segments. `tests/test_urls.py`: 125 parametrized cases.
