# T28: Shared test fixtures for owned threads and loopback servers

**Outcome:** Implemented; `owned_threads` and `loopback_server` own what a test starts and fail it if anything survives. Review passed after four Blocking findings were fixed.

Shared test fixtures for owned threads and loopback servers. Evidence: validated; the T20 review needed three rounds to make one test server and its regression test join every thread on failure paths ([T20](../closed/T20.md#review)), and T21–T24 each wrote their own join-in-`finally` code. Paths: `tests/conftest.py`, the tests that start threads or servers, `tests/README.md`, which owns the test conventions (the fixtures' usage). Outcome: fixtures that start threads or a loopback HTTP server for a test and, in teardown, stop them, join them (including handler threads) and fail the test if any survives. Validation: a regression test per fixture showing that a deliberately leaked thread fails teardown; existing tests migrated without weakening their assertions. Dependencies: none.

## Origin and boundary

Planned from the T20 review evidence above, and revalidated at `eb0f96f`: `tests/test_youtube.py`, `tests/test_worker.py` and `tests/test_store.py` each join their own threads by hand.

- **Intent:** a test cannot leave work behind it, and forgetting a join is no longer possible ([AGENTS](../../AGENTS.md#tests)).
- **Dependencies:** none.
- **Implementation direction:** `tests/conftest.py` with `ThreadOwner` and `LoopbackServer`, exposed as the `owned_threads` and `loopback_server` fixtures. Every stop runs before any join, so threads waiting on separate stops all end. The server records each handler thread before starting it and joins them with a bound.
- **Decisions within DESIGN's latitude (assumptions):** owned threads are daemons, so a survivor is reported instead of hanging the interpreter. The test that a `LoopbackServer` close waits for its handlers is replaced by `test_a_running_request_handler_is_joined` and `test_a_leaked_request_handler_fails_teardown`, because the server no longer joins in `server_close`; the property, that no handler outlives its test, is kept and now also holds within a bound. Threads the application's lifespan starts stay with the application's own shutdown tests.
- **Compatibility surface:** tests only. No HTTP contract, setting or on-disk layout.
- **Non-goals:** changing what the migrated tests assert; application code.
- **Validation:** `tests/tooling/test_fixtures.py` runs each fixture's leak and clean cases in nested pytest processes; the migrated tests keep their assertions.
- **Mutation evidence:** survivors not reported; stops skipped; a join before the other stops; handlers not recorded; the server not shut down.
- **Done:** gates, review, closed record. No host checks.

## Implementation

- **`tests/conftest.py`:** `ThreadOwner` runs every stop, even if one raises, then joins every thread within its bound, then reports. `LoopbackServer` records each handler thread before starting it. `owned_threads` and `loopback_server` expose them.
- **`tests/tooling/test_fixtures.py`:** runs each fixture's leak and clean cases in nested pytest processes.
- **Migrated:** `tests/test_store.py`, `tests/test_worker.py` and `tests/test_youtube.py`. Their assertions are unchanged. `tests/README.md` names the fixtures.
- **Removed:** `test_loopback_server_close_waits_for_request_handlers`, because the server no longer joins inside `server_close`. `test_a_running_request_handler_is_joined` and `test_a_leaked_request_handler_fails_teardown` keep the property, that no handler outlives its test, and M5 and M6 below show them failing when it breaks.
