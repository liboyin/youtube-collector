# T39: Make configured Firefox authentication available to caption acquisition

**Priority:** Medium, deferred until a real run with cookies shows how the backend behaves (DESIGN C52).

**Deferral (2026-11-09):** the user chose to pick the backend after authorizing a small run with cookies. Revisit trigger: that authorization, under [T25](T25.md). Source inspection of youtube-transcript-api 1.2.5 and yt-dlp 2026.10.26 found the following; none of it has been tried against YouTube. The transcript library has cookie loading commented out and calls the player endpoint as the `ANDROID` client, so giving it a cookie jar does not establish authentication; it reports gating as `AgeRestricted`, `RequestBlocked` or `VideoUnplayable`. yt-dlp lists manual tracks in `subtitles` and generated ones in `automatic_captions`, where a translation carries `tlang` in its URL. It skips tracks with only a warning when YouTube requires a PO token, which could be misreported as `unavailable`, and it has one socket timeout where D38 requires separate connect and read timeouts. The options offered were a yt-dlp fallback only for gated videos when cookies exist (recommended, keeping the public path that T25 verified), or moving all captions to yt-dlp, which would need DESIGN 5.6 and D38 superseded and would make [T38](T38.md) unnecessary.

Evidence: [review D2](../../project-review-2026-11-10.md#d2--media-authentication-and-caption-authentication-are-different-capabilities), source inspection at `d565907039b7550f550d860f3d4fdd2891ebc8d4`. `default_components` enables Firefox cookies only for yt-dlp; the caption adapter creates a separate unauthenticated Session. The installed transcript library comments that its cookie authentication is disabled. No private-video failure was reproduced. The user explicitly identified this capability gap as an issue; DESIGN C49 records the desired outcome.

Paths: `youtube_collector/captions.py`, `youtube_collector/youtube.py`, composition in `youtube_collector/api.py`, worker integration, tests and cookie operating guidance. Outcome: caption acquisition can use the configured Firefox authentication when needed, retaining unauthenticated operation when no profile is available. Investigate supported backend capabilities before choosing an implementation; merely passing a session to the current transcript client does not establish authenticated support. Preserve manual/generated precedence, language matching, translation exclusion, SRT output, timeout and failure-outcome contracts unless the user explicitly accepts changes. Record the chosen design before implementation; do not assume that consolidating all caption work into yt-dlp is already authorized.

Validation: offline tests with synthetic credentials and owned response fixtures proving authentication routing and preserved caption semantics without reading a real profile or reaching YouTube; targeted mutation evidence for credential handling and incorrect acknowledgement. Any authenticated real-service verification requires separate explicit authorization and belongs with [T25](T25.md); built-image checks remain [T10](T10.md). Dependencies: backend feasibility and accepted implementation design; coordinate session ownership with [T38](T38.md). Hard-link testing remains solely in T25.
