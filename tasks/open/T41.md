# T41: Publish the SRT before the MP4

**Priority:** Medium. Decided by DESIGN C57.

Evidence: design decision from the 2026-11-14 review. Today a `videos-with-captions` item publishes its MP4, then fetches and publishes captions, so a person watching the share sees the MP4 before the item is complete. Two files cannot be published atomically; publishing the MP4 last makes it the completion signal.

Outcome: for an item that needs both artifacts, the worker downloads the media into scratch ([T40](T40.md)), fetches the captions, publishes the SRT, then copies and publishes the MP4. Every outcome of DESIGN 5.7 is kept, and the tests must show each case: a failed media download skips captions and leaves the captions outcome null; captions `unavailable` or a caption-service `error` still publish the MP4 and leave the item `done`; a caption error that fails the item (malformed payload, SRT publication failure) still publishes the downloaded MP4, as today, and records media `downloaded` on the failed item; a failed MP4 copy or publication after the SRT was published fails the item with captions `downloaded` kept. Items that need only one artifact are unchanged, as is the C33 rule that a new SRT takes the stem of a single existing MP4.

Assumption to confirm with the user if the executor finds a reason to differ: "a downloaded MP4 is always published" preserves today's observable results; the alternative, discarding a good download because its captions failed, was not chosen. The SRT's name must equal the MP4's stem although the MP4 is not yet on the share, so both names derive from the same title.

Paths: `youtube_collector/worker.py`, `tests/test_worker.py`, DESIGN 5.7 (replace its "Planned" note) and section 3's workflow text, README if it describes the order. Compatibility surface: no schema, setting or layout change; only the order in which the two files appear.

Validation: a test that observes the staging directory at the moment the MP4 is published and finds the SRT already present; the outcome cases above; a restart case in which the SRT exists alone and the next attempt reports captions `existing` and media `downloaded`. Mutation evidence is required for the order itself and for "media outcome and failure records are unchanged by the reordering". Non-goals: per-video folders, any change to caption selection. Dependencies: [T40](T40.md).
