# T43: Name the Firefox profile with an explicit setting and report missing cookies

**Priority:** Medium. Decided by DESIGN C56.

Evidence: design decision from the 2026-11-14 review. `youtube.firefox_profile_roots` copies yt-dlp's five internal profile locations, Compose mounts the profile at a fake snap path to match one of them, and when no cookie database is found the service only logs an info line. With the default empty named volume the service cannot tell "cookies not wanted" from "profile mounted wrongly".

Outcome: a setting, proposed as `COLLECTOR_FIREFOX_PROFILE`, names the profile directory, and the adapter passes that path to yt-dlp's `cookiesfrombrowser`. Three conditions are distinguished once at startup, by file names only: not configured (info log; no cookies); configured and a `cookies.sqlite` present (cookies used); configured but none present (warning log, a warning in `/health`, and the service runs without cookies). `/health` gains a cookies section and a list of warnings; warnings never change the 200 or 503 status. `firefox_profile_roots` and the search over several roots are removed.

Direction, to be revalidated against the locked yt-dlp source, not memory: that `cookiesfrombrowser` accepts a profile path and which directory layouts it then searches, so the service's own presence check matches what yt-dlp will find. Compose mounts the profile read-only at a neutral path and sets the variable only when `FIREFOX_PROFILE_DIR` is set; verify the interpolation form with `docker compose config` as README Testing describes. The real-data devcontainer layer mounts the same profile and must follow.

Safety: tests use synthetic profile directories under `tmp_path`; nothing reads, opens or copies a real profile, and the service's own check looks at names only ([AGENTS](../../AGENTS.md#safety)).

Paths: `youtube_collector/youtube.py`, `youtube_collector/config.py`, `youtube_collector/api.py`, `youtube_collector/responses.py`, `docker-compose.yaml`, `.devcontainer/real-data/docker-compose.real-data.yaml`, tests, README (configuration tables), DESIGN 5.11 (replace its "Planned" note), 5.14, section 7 and section 14, and the mount path mentioned in [T10](T10.md). Compatibility surface: a new setting, a changed mount path inside the container, new `/health` fields; `FIREFOX_PROFILE_DIR` keeps its meaning for the user.

Validation: settings tests; adapter tests that the option carries the configured path and is absent when unset; API tests for the three conditions and for the status code staying unchanged by a warning; simulated `docker compose config` output for both the set and unset cases, labelled simulated. Host check for T10: the mount is read-only at the new path. Non-goals: caption authentication ([T39](T39.md)), detecting stale cookies ([T44](T44.md)). Dependencies: none. The first cookie run under [T25](T25.md) should use this setting.
