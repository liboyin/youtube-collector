# T48: Script the image checks that need no YouTube

**Priority:** Low. Decided by DESIGN C58.

Evidence: planning step. [T10](T10.md) lists the built-image checks as prose the user performs by hand on a Docker host: build, start, `/health` 200 and 503, a graceful stop within the grace, Docker's escalation, restart recovery. They are repeated after every image change and are easy to perform slightly differently each time.

Outcome: one host script that builds the `runtime` image and runs those checks against a throwaway deployment, prints each result, and exits non-zero on the first failure. It must be unable to touch the real deployment: its own Compose project name, a temporary staging directory holding the marker, its own database and scratch volumes, no Firefox profile, and a port that cannot collide with the service. It submits nothing, and a new database holds no work, so the worker never contacts YouTube; the script verifies that the database is new before starting.

Cleanup, authorized by the user on 2026-11-14: the script may run `docker compose down -v` against its own throwaway Compose project, and only that project, to remove the volumes it created. [AGENTS](../../AGENTS.md#safety) requires explicit authorization for that command because it destroys the service's job and failure records; this authorization does not extend to the `youtube-collector-service` or `youtube-collector` projects, or to an agent running the command by hand. The script must therefore pass its own project name explicitly on every Compose command, refuse to run if that name equals either real project name, and be shown by its tests never to issue `down -v` for any other project.

Constraints: the dev container has no Docker daemon, so an agent can write and statically check the script but cannot run it. Its first real run is a host check the user performs and reports, recorded under T10; any result obtained without Docker is labelled simulated. The script must never run `down -v`, `stop` or `kill` against the `youtube-collector-service` or `youtube-collector` projects.

Paths: a new script at the repository root, README Testing, [T10](T10.md), `.dockerignore`. Compatibility surface: none for the service. Validation: shell tests in `tests/tooling/` with a stub `docker` on `PATH` that record the commands issued and prove the project name, the absence of the production mounts and the refusal paths; then the user's host run. Dependencies: after [T40](T40.md) and [T43](T43.md), which change the volumes and mounts it must cover; after [T35](T35.md) for the restart check.
