# T42: Judge staging staleness only when the worker can touch the share

**Priority:** High. Decided by DESIGN C55.

Evidence: validated by source inspection in the 2026-11-14 review. `/health` returns 503 when the worker's cached marker check is older than 120 seconds, and the worker refreshes it only between steps and from yt-dlp's progress hook. A long ffmpeg merge, a paced playlist expansion or a long pre-download sleep therefore reports an unhealthy service although the share is fine. Nothing acts on `/health` today, so no data is at risk, but any future healthcheck would restart healthy downloads.

Outcome: the worker records whether its current step can touch the share. `/health` applies the age limit to the cached check only while the worker is idle, paused, or in such a step: the marker checks, listing the destination, the copy to the share and publication. During the other steps (playlist expansion, metadata, the download and merge in scratch, caption requests) it reports the last result and its age without calling it stale. The copy loop from [T40](T40.md) refreshes the check as chunks complete, so a slow copy stays healthy and a stalled one goes stale. Refreshing means checking the marker again between chunks, at an interval, not merely stamping the time: a successful write does not show that the marker is still present. `/health` also reports the worker's current activity and how long it has lasted, for information only: it never changes the 200 or 503 status, because no threshold separates a long download from a hang.

This removes the download heartbeat: the `on_activity` parameter of `MediaSource.download_media` and `YoutubeClient.download_media`, yt-dlp's progress hook, `Worker._marker_heartbeat` and `marker_check_interval`. No thread is added (C55 rejects a probe thread). The value the API thread reads must be published as one immutable object, as `StagingCheck` is now.

Paths: `youtube_collector/worker.py`, `youtube_collector/youtube.py`, `youtube_collector/api.py`, `youtube_collector/responses.py`, tests, DESIGN 5.13, 5.14 (replace its "Planned" note), the implementation defaults in section 7 and section 14, README. Compatibility surface: `/health` gains fields and the meaning of `staging.ok` changes as described; existing fields keep their names and types. C25 is preserved: the API still never touches the share.

Validation, with injected clocks only: health stays 200 while a fake download or expansion outlasts the limit; it turns 503 when a share step outlasts it and when the idle worker stops checking; a missing marker still reports `paused` and 503; the activity fields follow the worker through an item. Mutation evidence is required for "a stalled share step is reported" so the fix cannot degrade into never reporting staleness. Non-goals: a Docker healthcheck, any new thread, changing the 120-second default. Dependencies: [T40](T40.md). Coordinate with [T43](T43.md) and [T44](T44.md), which also add fields to `/health`.
