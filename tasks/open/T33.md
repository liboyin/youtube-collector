# T33: Simplify the job lifecycle

**Priority:** High.

Remove the change feed, revisions, tombstones, reconciliation, in-process notification, long polling, byte progress and idempotency keys, as decisions C39–C44, C46 and C47 require. Evidence: `store.py`, `api.py`, `worker.py`, `config.py`, `reconcile.py` and `notify.py` implement them.

## Origin and boundary

Planned from the disposition of the 2026-11-08 architecture review ([T29](../closed/T29.md)) and the workflows the user then described. These changes share one candidate because they all reshape the same tables and the same job representation; none has a useful state on its own.

- **Intent:** DESIGN 5.1, 5.8, 5.9, 5.10, 5.14, 6, 7 and 10: "submit, poll, read". Finished jobs stay readable for the retention period, whatever happens to their files, and a job's representation embeds its uncleared failures. The only background actor is the YouTube worker.
- **Dependencies:** C39–C44, C46, C47. Runs after [T32](../closed/T32.md), which touches the same test files.
- **Implementation direction:**
  - `store.py`, schema version 2: no `meta` or `idempotency_keys` table; no `revision`, `removed_at` or `removal`; no byte columns; `items.job_kind` and `failures.updated_at` go; `jobs.finished_at` is new. `submit(..., retention_seconds=)` returns the job's record and deletes expired jobs and their items first, in its own transaction. `_update_job` stamps `finished_at` when a job becomes finished. Clearing and superseding a failure deletes its row. `_job_record` embeds the job's uncleared failures. Removed: `Submission`, `ChangePage`, `CursorPruned`, `IdempotencyConflict`, `ItemFiles`, `JobView`, `Snapshot`, `KEY_RETENTION_SECONDS` and every method that served them.
  - `worker.py`: no `notify` or byte-progress writes. `StagingCheck` moves here; `staging_check()` returns the latest. Every marker check goes through one method that records it, and a download's activity callback repeats the check once per `marker_check_interval` (30 s).
  - `youtube.py`: `download_media` takes a no-argument `on_activity` callback in place of byte reports; `_ProgressHook` goes.
  - `api.py`: no notifier, reconciler, change feed, wait parameters or 409/200 responses. `GET /jobs` returns `{jobs}`, `GET /failures` returns `{failures}`, `GET /jobs/{id}` returns the job, and `/health` reads the worker's check and reports only the worker thread.
  - `config.py`: `COLLECTOR_RECONCILE_INTERVAL` and `COLLECTOR_MAX_WAIT` go; `COLLECTOR_TOMBSTONE_RETENTION_DAYS` becomes `COLLECTOR_JOB_RETENTION_DAYS`.
  - Deleted: `reconcile.py`, `notify.py` and their tests. Documentation: README, `docker-compose.yaml`, DESIGN section 14 and its status note, [T10](T10.md) and the review skill's scrutiny list.
- **Behavior carried by the removed layers:**

  | Layer | Unique behavior | Owner afterwards | Verification |
  |---|---|---|---|
  | Reconciler | Cached marker check, with its age, for `/health` (C25) | `Worker.staging_check` (C43) | Health tests; a test that a long download refreshes the check |
  | Reconciler | Bounding the status table by pruning | `Store.submit` deletes expired jobs (C42) | Store tests of the cutoff, of unfinished jobs and of failures outliving jobs |
  | Reconciler | Thread that stalls on the share while the API stays responsive (C25) | The worker, the only thread touching the share | API test with the worker blocked in a marker check |
  | Reconciler | Marker pause and resume warnings | The worker already logs its own | Existing worker test |
  | Reconciler | Dropping records of moved files, `reconciled_at` | Removed (C40) | Test that a job stays readable after its file is gone |
  | Notifier | Waking long polls | Removed (C41) | No waiters remain |
  | Change feed | Ordering, coalescing, resynchronization, 410, `view_revision` | Removed (C39) | Absence of the route, verified directly |
  | Idempotency keys | 200 on replay, 409 on conflict, final representation | Removed (C46); a repeat creates a job that finds `existing` | Worker test of a repeat submission making no YouTube call; test that the old field is rejected with 422 |
  | Byte progress | `progress` on items, throttled writes | Removed (C41); the callback survives as the marker heartbeat | Throttle test on marker checks |
  | Worker's `notify` | Signalling after each write | Removed; `Worker.wake` on submission stays | Submission test's bound |

- **Decisions within DESIGN's latitude (assumptions):** a job's `updated_at` keeps meaning a change to the job row, as today. `finished_at` is internal and not reported. The expiry comparison is `finished_at <= now - retention`. The request model keeps `extra='forbid'`, so `idempotency_key` now answers 422.
- **Compatibility surface:** every HTTP response changes as above, and `GET /jobs/changes` is gone. Removed and renamed environment variables are listed under Implementation direction. A database at schema version 1 is refused at startup. No compatibility is kept (C44). The endpoints in DESIGN section 6, their other status codes, and `docker compose` service shape are preserved.
- **Non-goals:** typed response models (T31); a running service against real YouTube (T25); any change to round-robin scheduling, publication or failure categories.
- **Validation:** rewritten `tests/test_store.py`, `tests/test_api.py`, `tests/test_worker.py`, `tests/test_config.py` and `tests/test_youtube.py`. `docker compose config` with the standalone binary for the production stack, labelled simulated, and T10's host checks updated.
- **Mutation evidence:** unfinished jobs never expire; failures survive their job's expiry; the retention cutoff; expired jobs' items deleted with them; cleared and superseded failures disappearing from the job; the marker checked before work and before publication; the download heartbeat refreshing the check and being throttled; `/health` honoring a stale check and a dead worker; submissions waking the worker.
- **Done:** gates, adversarial review, closed record; host checks in T10.
