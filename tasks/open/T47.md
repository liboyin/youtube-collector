# T47: Offline end-to-end tests of both workflows against a real service process

**Priority:** Medium. Decided by DESIGN C58.

Evidence: validated by reading the tests. The process-level tests in `tests/test_main.py` cover shutdown and restart only. Nothing drives DESIGN section 3's two workflows through a real process and real HTTP: the in-process API tests use `TestClient`, and the worker tests call `step` directly.

Outcome: the lifecycle harness (`tests/lifecycle_service.py` and the `lifecycle` fixture) gains end-to-end tests with fake adapters, a test-owned database and staging directory, and real HTTP: the orchestrator path (submit one `videos-with-captions` job, poll `GET /jobs/{id}` to `finished`, find both files and the reported paths, including captions `unavailable` and `error`); the manual path (a playlist job, files in the playlist folder, a failing entry visible in `GET /failures` and cleared by `DELETE`); a repeated submission reporting `existing` with no second download; the marker removed and restored, with `/health` reporting the pause and work resuming unaided.

Also in scope: replace the harness's fault injection through the store's clock. `controlled_clock` blocks a transaction by blocking the clock it reads, keyed on thread names; it breaks silently if a write stops reading the clock or a thread is renamed. Give the fake components an explicit hook instead, and keep the five existing lifecycle tests passing on it.

Constraints: every child process is killed and reaped on every path, as the fixture does now; the fake playlist adapter replaces the `NotImplementedError` stub; no test reaches an external service, and the subprocess inherits the same guarantee ([T50](../closed/T50.md) if it has landed). Crash-and-restart and scratch-directory scenarios belong to [T35](T35.md) and [T40](T40.md), which own their own lifecycle tests; this task covers the workflows as the code stands when it runs, and says which of those tasks had landed.

Paths: `tests/test_main.py` or a new `tests/test_e2e.py`, `tests/lifecycle_service.py`, `tests/README.md`. Compatibility surface: none; tests only. Validation: each scenario fails under a targeted break of the behavior it protects, shown for at least one scenario per workflow; suite time stays reasonable and is reported. Dependencies: none strictly; cheaper after T35 and T40–T42, which change the same harness.
