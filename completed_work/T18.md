# T18: Failure categories

## Origin and boundary

Planned by [T9](T9.md). The accepted boundary, as it stood in TODO:

- **Intent:** DESIGN 5.9's category hint and raw message.
- **Implementation direction:** a `Category` string enum with the six DESIGN values; `categorize(error)` and `failure_message(error)` (the error's text, or its type name when the text is empty). Typed rules are applied first along the error's chain (`exc_info` as yt-dlp's `DownloadError` carries it, `__cause__` and `__context__`): `youtube-transcript-api`'s `RequestBlocked`, `PoTokenRequired`, `AgeRestricted` and `FailedToCreateConsentCookie` are `blocked`; `VideoUnavailable`, `VideoUnplayable` and `InvalidVideoId` are `unavailable`; `YouTubeDataUnparsable` is `extractor`; `YouTubeRequestFailed` and `requests` exceptions are `network`; `TimeoutError`, `ConnectionError` and `socket.gaierror` are `network`, and other `OSError`s `filesystem`. Otherwise case-insensitive message patterns are tried in the order `blocked`, `unavailable`, `filesystem`, `network`, `extractor`, falling back to `internal`. yt-dlp is not imported: its errors are recognized by attribute and message, so T18 does not depend on T20.
- **Compatibility surface:** the later `category` and `message` fields of failure records (T19, T24); categories are a documented hint, and the message stays authoritative.
- **Non-goals:** deciding which errors are failures (T21), and the phase, which the caller supplies.
- **Validation:** tests with representative yt-dlp messages for each category, every listed caption exception, chained and wrapped errors, and the fallback. No mutation evidence is required: categories are hints that never change an outcome.

## Implementation

`youtube_collector/categories.py`: the `Category` enum, `categorize` with the typed rules and the ordered message patterns the boundary lists, and `failure_message`. The chain walk follows `exc_info`, `__cause__` and `__context__` breadth-first, visiting each error once, so cyclic chains terminate. The `ssl` pattern matches the whole word only. `tests/test_categories.py` has 52 cases, with a fake that carries `exc_info` the way yt-dlp's `DownloadError` does.

Revalidated during implementation: DESIGN 5.9 lists private videos as `unavailable`, so yt-dlp's "Private video. Sign in if you've been granted access" is `unavailable`, not `blocked`. `youtube-transcript-api` 1.2.5 raises `IpBlocked` for HTTP 429 itself, so a caption 429 is `blocked` by type.

## Review

Codex `gpt-6.1-sol`, medium effort (dispatch arguments), thread `01a1b68a-7b61-7082-bff0-cad07b8b458a`, on the worktree's dirty tree.

- **First assessment:** the reviewer ran the 50 tests then present (seed 1801) and checked the real `DownloadError.exc_info` shape and the exception inheritance against the fakes. It found one Blocking finding. `failure_message` used `str(error).strip()`, which altered nonempty text and turned whitespace-only text into the type name, contrary to DESIGN 5.9's "raw error text, always kept". It was validated by reading the code, and fixed by returning `str(error) or type(error).__name__`, with regression cases for surrounding and whitespace-only text.
- **Follow-up:** the reviewer confirmed that only the fix had changed, replayed T18-M1 with verified scratch imports (2 failed, 50 passed) and reported the finding resolved. Verdict: no blocking findings and no new findings.

Integrity snapshots matched after both assessments.

## Limitations

- Message patterns were written from yt-dlp's message wording, not from messages captured from live YouTube; their accuracy is a hint by design, and T25's end-to-end run may refine them.
