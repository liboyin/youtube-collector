# T2: Devcontainer storage separation and the real-data configuration

## Origin and boundary

From the 2026-11-07 project review of `ca869a8`; decision C28 in [DESIGN](../DESIGN.md#11-decisions-agreed-in-discussion-2026-11-06). Delivered in one commit with [T5](T5.md), because both define which host data and secrets the devcontainer can see and both edit `.devcontainer/devcontainer.json`. Accepted boundary, recorded in the working review record before review:

- **Intent:** the default devcontainer replaces every production mount, through Compose `!override`, with development-only named volumes (`dev_staging` for the staging path, `dev_db` for the database) and mounts no browser profile, whatever `ASSETS_DIR` and `FIREFOX_PROFILE_DIR` say. A second configuration, `.devcontainer/real-data/` ("youtube-collector (REAL DATA)"), layers the real share and a read-only profile on top, keeps `dev_db`, sets `COLLECTOR_REAL_DATA=1`, and fails at interpolation when either variable is unset or empty. The fixed `container_name` goes; the production profile mount becomes `:ro`.
- **Compatibility surface:** Compose service mounts and environment (production: the profile becomes read-only, otherwise unchanged; devcontainer: every mount changes), container naming. No HTTP contract or application on-disk layout exists yet.
- **Non-goals:** base image, Deno and lock checks (T3, T4, T8), dependency changes (T6), any access to real data, the real profile or YouTube, and giving the real-data configuration the production database.
- **Validation and done criteria:** Compose renders and fail-fast checks, JSONC parsing, the three gates, review without unresolved Blocking findings.

## Implementation

- `docker-compose.yaml`: no `container_name`; the profile mount is `:ro`, with the reason (yt-dlp copies `cookies.sqlite` before opening it, verified in the locked yt-dlp source on 2026-11-07).
- `.devcontainer/docker-compose.devcontainer.yaml`: `volumes: !override` with `dev_staging` and `dev_db`.
- `.devcontainer/real-data/devcontainer.json` and `docker-compose.real-data.yaml`: the opt-in configuration. Its `devcontainer.json` duplicates the default one except for the name and the extra Compose file, because JSON has no includes; both files say to keep them in step.
- `Dockerfile`: also creates `/workspaces/youtube-collector/assets` owned by `ubuntu`, so a new `dev_staging` volume initializes writable for the runtime user.
- README (dev container and configuration sections) and AGENTS (the real-data configuration is subject to every host-data rule and authorizes no run).
