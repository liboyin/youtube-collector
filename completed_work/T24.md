# T24: HTTP API, configuration and service entrypoint

## Origin and boundary

Planned by [T9](T9.md). The accepted boundary, as it stood in TODO, including gap 4 from the gap review of `8c7c3fc..2461280`:

- **Intent:** DESIGN 5.1, 5.8's `GET /jobs`, 5.10's endpoints, 5.14 and sections 6 and 7: compose T15–T23 into the running service.
- **Implementation direction:**
  - `youtube_collector/config.py`, `Settings.from_environ`, reads the variables in README's table, with DESIGN section 7's defaults. Empty counts as unset; invalid values raise `SettingsError` naming the variable. It also holds the C35 implementation defaults: a 2 s wait for `GET /jobs`'s pass, 120 s for a stale staging check, and a 30 s shutdown grace.
  - `youtube_collector/api.py`, `create_app(settings, components_factory)`:
    - The lifespan creates the database, detects cookies once (in `default_components`), binds the notifier, and starts the worker and reconciliation threads. On shutdown it stops both, joins them within the grace, and otherwise abandons the worker to restart recovery (C36).
    - Database calls run on one dedicated thread with its own store, never on the event loop. Long polls wait on the loop through the notifier.
    - **Submissions:** pydantic bodies. `videos` forbids `languages`, and the caption kinds require at least one well-formed tag. URLs are validated by T15, and failures give 422 with the reason. The idempotency body is the kind, URL and languages. A new job returns 202 and wakes the worker; a replay returns 200 (live or final representation), and a conflict returns 409.
    - **`GET /jobs`:** requests a pass, waits a bounded time without touching the share (C25), and returns `jobs`, `revision` and `reconciled_at`.
    - **`GET /jobs/changes`:** `since`, `wait` capped at `max_wait`, and `limit` up to 1000; returns `changes`, `cursor` and `more`, or 410 below the pruned-through revision.
    - **`GET /jobs/{id}`:** optional `since` and `wait`; returns the job with `view_revision`, or 404.
    - **Failures:** `GET /failures` returns `failures` and `revision`; both deletes return the cleared records, and an unknown or already-cleared failure is 404.
    - **`GET /health`:** database check, cached staging check with its age and paused state, thread liveness and the yt-dlp version; 200 or 503 with the same body.
    - Unexpected errors keep FastAPI's generic 500 and are logged.
  - `youtube_collector/__main__.py` runs one uvicorn process with a 5 s graceful window for open requests.
  - **Deployment:** `docker-compose.yaml` gains the command, environment, published port, `restart: unless-stopped` and a 45 s `stop_grace_period`. The dev container override resets the port and restart policy. README gains the runtime settings and "Running the service"; DESIGN sections 7 and 14 are updated.
- **Gap from the review of `8c7c3fc..2461280` (gap 4):** T23's `Notifier` takes an injectable monotonic clock for its long-poll deadline, but it really waits on asyncio's clock. A clock that does not advance in real time therefore never reaches the deadline: when the T24 draft passed the components' injected test clock, a long poll looped forever in short waits. Remedy within T24:
  - `_Runtime` builds its `Notifier` with the default `time.monotonic`. The injected clock still drives health's staging age, the worker and the reconciler.
  - `notify.py`'s docstrings state that the clock must advance in real time and match the event loop's.
  - The capped-wait test (`test_change_feed_and_job_waits_are_capped`) guards the composition.
- **Decisions within DESIGN's latitude (assumptions):**
  - A replayed idempotency key answers 200, a new job 202.
  - `GET /jobs/{id}` adds `view_revision`, the cursor for its own long poll.
  - Response bodies are plain JSON objects documented by the endpoint descriptions; DESIGN section 6 leaves exact schemas to implementation.
- **Compatibility surface:** every HTTP contract in DESIGN section 6, the environment variables, the Compose service's command, port and restart policy, and the dev container's resets.
- **Non-goals:** authentication (C7), several processes, typed response models beyond the request bodies, and running against real YouTube (T25).
- **Validation:**
  - Endpoint tests through `TestClient` with the real lifespan and threads, fake adapters, and test-owned staging and database. They cover each status code (202, 200, 404, 409, 410, 422, 503) and the long polls.
  - The API staying responsive while a reconciliation probe is blocked; shutdown stopping, or abandoning, the threads.
  - Settings parsing; the entrypoint with `uvicorn.run` patched.
  - `docker compose config` with the standalone binary for the production and dev stacks; T10 gains the host checks.
- **Mutation evidence:** for the 409/200/202 distinctions, the `wait` cap (which also kills a notifier built on a frozen clock), the 410 mapping, the `jobs_reconcile_wait` bound, health's verdict, waking the worker on submission, and stopping the worker on shutdown. The first run (2026-11-07) was stopped unfinished at the user's request and must be repeated.
- **Done:** gates, review and a completion record; the host checks stay in T10.

## Implementation

- **`youtube_collector/config.py`:** `Settings` and `SettingsError`.
- **`youtube_collector/api.py`:** `create_app`, `Components`, `default_components`, and `_Runtime`, which owns the threads, the notifier and the API's database thread. The API's store opens lazily inside each operation on a single-thread executor, so a failure to open is an ordinary `sqlite3.Error` that the next call retries. Shutdown closes the store only if it was opened and always shuts the executor down.
- **`youtube_collector/__main__.py`:** `main`.
- **`youtube_collector/store.py`:** `Store.check`, which takes the write lock and commits nothing.
- **`youtube_collector/notify.py`:** a docstring states gap 4's clock constraint.
- **Deployment and documentation:**
  - `docker-compose.yaml` gains the command, environment, port, restart policy and stop grace.
  - The dev container override resets the port and the restart policy.
  - README gains the runtime settings table and "Running the service".
  - DESIGN section 7 names the variables and implementation defaults, and section 14 lists the new modules.
- **Tests:** `tests/test_api.py` (32), `tests/test_config.py` (14), `tests/test_main.py` (3), and two new `check` tests in `tests/test_store.py`.

Found during implementation, before the freeze:

- **The notifier's clock (gap 4):** the injected test clock never reached a long poll's deadline, so the notifier now uses the real monotonic clock.
- **The entrypoint test:** a `runpy` test raised a `RuntimeWarning`, so it now runs on a fresh module.

## Review

Codex `gpt-6.1-sol`, medium effort (dispatch arguments), thread `01a1b875-ee1d-7e50-91ab-901239aa163c`, on the worktree's dirty tree.

- **First assessment:**
  - **Blocking finding 1:** a SQLite error while the API thread opened its connection, raised in a `ThreadPoolExecutor` initializer, broke the pool for good. `/health` then answered a generic 500 instead of 503, and shutdown raised `BrokenThreadPool` before shutting the executor down. Validated and fixed as described under Implementation, with two tests.
  - **Non-blocking finding 2:** Compose does not pass `COLLECTOR_SHUTDOWN_GRACE` through, although README implied it did. Validated; README now says Compose leaves it out, because Docker's 45 s stop grace must stay above it, and that both values change together.
- **Follow-up:** both findings resolved, no new findings. Verdict: no blocking findings.

Integrity snapshots matched after both assessments.

- Nothing has run against real YouTube; T25 needs the user's authorization.
