# T1: Devcontainer and project skeleton

## Origin and boundary

Requested by the user on 2026-11-06, so later work runs in the repository's own devcontainer instead of the `youtube-whisperer` one. Accepted boundary, as recorded in TODO before implementation:

- **Intent:** give the repository its own image, Compose file and devcontainer, following `youtube-whisperer`'s build design at `474f5dc`: shared `docker-build-common` helpers pinned at `v1.2.0`, a uv-locked venv at `/opt/venv` built from the distro's Python 3.12, `runtime` and `dev` targets with dev tools only in the devcontainer image, `PYPI_PROXY`/`APT_PROXY` support, and a creation hook that checks the lock offline and installs Claude Code and Codex.
- **Implementation direction:** `ubuntu:24.04` base (no CUDA); `ffmpeg`, `git`, `curl`, `unzip` and Deno; one Compose service `app` mounting the staging directory (`ASSETS_DIR`), the Firefox profile (`FIREFOX_PROFILE_DIR`) and a `collector_db` named volume at `/var/lib/youtube-collector`, created in the image and owned by the runtime user; runtime dependencies from DESIGN; an empty `youtube_collector` package measured by coverage; `uv.lock`; `update-dependencies.sh` and its test, which also serves C19; a full README.
- **Compatibility surface:** none; no HTTP contract, setting or on-disk layout existed.
- **Non-goals:** application code, the service entrypoint and published port, `.env` handling for application settings, changes to `youtube-whisperer`.
- **Validation and done criteria:** offline lock check, the three gates, copies matching their sources except for documented edits, adversarial review; the image build cannot run without Docker and is recorded as a limitation.

## Review

Codex `gpt-6.1-sol`, medium effort, session `01a1b191-41ae-7e63-89d2-7837898c7a7d`. Integrity snapshots matched before and after both rounds.

- **Round 1, Finding 1 (Blocking), Validated, fixed:** plain `ubuntu:24.04` has no CA certificates, and the apt helper installs with `--no-install-recommends`, so the HTTPS Deno download and the Git fetch of `pathlib-extensions` would fail verification; `curl | sh` would also hide the failed download. The reviewer established this from the image manifest and an isolated apt simulation. Fix: `ca-certificates` in the apt list, and `deno --version` after the installer.
- **Round 2 (Dockerfile delta):** finding resolved, no new findings. Verdict: no blocking findings.
- The inherited coverage-threshold finding deferred in `1f66194` keeps its disposition.

## Limitations

- Docker is unavailable in the `youtube-whisperer` devcontainer, so the image build, `docker compose config` and devcontainer creation were not run. The first real check is the user opening the devcontainer, which also verifies the `ca-certificates` fix, the Deno install and the Git dependency fetch.
- If `.env` sets `ASSETS_DIR` or `FIREFOX_PROFILE_DIR`, the devcontainer mounts the real staging share or browser profile, as in `youtube-whisperer`; AGENTS.md forbids development runs from using them.
- Working evidence lived in session scratch storage and is not retained beyond this record.
